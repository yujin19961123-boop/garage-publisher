# 原型文件上传

创建和更新使用同一个文件选择器，不需要切换上传模式。

- 直接选择或拖入单个 `.html` / `.htm` 文件，任意文件名均可，例如 `prototype.html` 或 `产品原型.HTML`，无需手动改名。单文件所需本地资源应内联。
- 点击“选择文件夹”，选整个 dist 或其他包含完整网页的文件夹。
- 将整个文件夹拖入上传区域。
- 打开 dist，全选其中的文件和子文件夹，拖入上传区域。
- 使用“选择文件”多选文件（文件选择器不能同时选择子文件夹；包含子文件夹时使用拖拽或选择整个文件夹）。
- 单独选择或拖入一个 ZIP，根目录直接包含首页或带外层 dist 均可。

文件夹和散文件由浏览器自动整理为ZIP。前端检查文件数量、大小、路径、重复、隐藏文件和可识别首页，再创建项目或发送更新。处理时显示进度，重复提交被禁止；打包支持取消。

后端先验证原始ZIP条目再安全解压，实际字节计入容量限制；根目录有index.html时直接使用，否则仅剥离唯一外层文件夹链。忽略系统元数据后只剩一个 HTML 文件时，将处理副本改名为 `index.html`；直接文件选择、文件拖拽、仅含单 HTML 的文件夹及 ZIP 使用同一规则，扩展名不区分大小写。本地原文件和原始 ZIP 均不改变。多个 HTML，或 HTML 加其他资源却没有 `index.html` 的多文件情况，不自动猜首页。系统元数据不发布，.env等隐藏文件仍拒绝。

发布时会在处理副本内适配HTML、CSS和JavaScript中的本地资源路径，支持常见的 `/assets/`、图片目录和 `/?...`、`/#...` 内部入口；外部网址保持不变。脚本通过语法树区分资源引用、实际导航地址与内部路由标识，避免误改正则表达式及业务路由。JavaScript 普通字符串仅对可识别的资源后缀或上传包中实际存在的文件做适配；`href`、`src`、`window.location.assign/replace` 等明确的地址位置另行处理。诸如 `/mobile/im/apps` 的内部路由字符串与模板保留原值，不能因为存在 `mobile` 资源目录就统一加前缀。真实 URL 的 `.pathname` 使用目录根路径正则校验时，支持限定范围的同源项目路径归一化，原正则与 URL 对象保持不变；现有小型脚本也可通过只读响应兼容，具体范围见 [URL 路径校验兼容](PATHNAME_COMPAT.md)。原始文件不修改，处理失败不影响已发布内容。原始源工程不能代替已导出的网页；任意运行时生成URL或框架路由逻辑仍不能保证全部自动修复。

单 HTML 改名和上传路径处理发生在新发布的暂存目录内，旧的已发布文件不会被重写。路径校验规则另有只读响应兼容，具体范围见上述说明；其他需要重新发布的规则仍从原始导出文件上传应用，遵循版本保留规则，不原地修改历史版本。

纯文件测试无需启动服务，也不会创建项目：

```powershell
node scripts/test-upload-inputs.mjs
```

覆盖任意文件名的单 HTML、中文和大写扩展名、嵌套单 HTML、整个文件夹、内容文件、多批目录读取、嵌套拖拽、ZIP直传、ZIP下载资源、非法与歧义路径、大小限制及取消。服务端Go测试覆盖单 HTML 改名、原 ZIP 不变、入口归一化与安全校验。

本地真实界面与发布流程验证：

```powershell
node scripts/test-single-html-local.mjs
```

此脚本仅连接本机，在唯一命名的临时项目中实际选择 `prototype.html` 并发布，再上传 `产品原型.HTML` 和包内单 `.htm` 的 ZIP 更新，检查原分享地址内容及页面按钮交互；多 HTML ZIP 失败后旧版继续可用。结束删除专用临时项目，比较原有项目和当前版本指向不变。报告 `.local/single-html-report.json` 为 `success:true, cleanup:true`，无脚本异常；390px 文件选择截图已查看。2026-11-17 经本次明确授权，已随 v0.4.1 同步上线，私有真实 HTTPS 验收报告 `.local/single-html-online-report.json` 同样成功，临时项目及文件已清理。部署与数据核对见 [生产发布记录](PRODUCTION_GARAGE.md)。
