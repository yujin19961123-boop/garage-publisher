# 原型文件上传

创建和更新使用同一个文件选择器，不需要切换上传模式。

- 点击“选择文件夹”，选整个 dist 或其他包含完整网页的文件夹。
- 将整个文件夹拖入上传区域。
- 打开 dist，全选其中的文件和子文件夹，拖入上传区域。
- 使用“选择文件”多选文件（文件选择器不能同时选择子文件夹；包含子文件夹时使用拖拽或选择整个文件夹）。
- 单独选择或拖入一个 ZIP，根目录直接包含首页或带外层 dist 均可。

文件夹和散文件由浏览器自动整理为ZIP。前端检查文件数量、大小、路径、重复、隐藏文件和可识别首页，再创建项目或发送更新。处理时显示进度，重复提交被禁止；打包支持取消。

后端先验证原始ZIP条目再安全解压，实际字节计入容量限制；根目录有index.html时直接使用，否则仅剥离唯一外层文件夹链。不从多个独立文件夹中任意挑选首页。系统元数据不发布，.env等隐藏文件仍拒绝。

发布时会在处理副本内适配HTML、CSS和JavaScript中的本地资源路径，支持常见的 `/assets/`、图片目录和 `/?...`、`/#...` 内部入口；外部网址保持不变。脚本通过语法树区分资源引用、实际导航地址与内部路由标识，避免误改正则表达式及业务路由。JavaScript 普通字符串仅对可识别的资源后缀或上传包中实际存在的文件做适配；`href`、`src`、`window.location.assign/replace` 等明确的地址位置另行处理。诸如 `/mobile/im/apps` 的内部路由字符串与模板保留原值，不能因为存在 `mobile` 资源目录就统一加前缀。原始文件不修改，处理失败不影响已发布内容。原始源工程不能代替已导出的网页；任意运行时生成URL或框架路由逻辑仍不能保证全部自动修复。

路径处理只发生在新发布的暂存目录内。发布台修复路径规则后，旧的已发布文件不会自动重写，需要从原始导出文件重新上传应用修复；重新上传仍遵循最近5个成功版本的保留规则，不原地修改历史版本。

纯文件测试无需启动服务，也不会创建项目：

```powershell
node scripts/test-upload-inputs.mjs
```

覆盖整个文件夹、内容文件、多批目录读取、嵌套拖拽、ZIP直传、ZIP下载资源、非法与歧义路径、大小限制及取消。服务端Go测试覆盖入口归一化与安全校验。
