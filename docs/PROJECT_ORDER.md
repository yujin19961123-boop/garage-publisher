# 项目排序

## 使用规则

- 默认最近更新在前。成功发布、实际切换到其他版本和修改名称都会更新时间；创建项目以创建时间为初始值。失败上传、重复切换当前版本、保存相同名称、手动排序不修改更新时间。
- 桌面从卡片空白处拖动，松开放置；按钮、链接、标题和时间文字不启动拖拽。跨过目标位置后其他卡片在280ms内平滑让位，虚线空位实时显示最终位置；松手后卡片以230ms动画落入空位，Escape 可以取消并恢复预览前顺序。预览不发送保存请求，松手才保存一次。
- 触屏正常滑动用于滚动；空白处长按350ms后拖动排序。键盘聚焦卡片后使用 Alt+方向键移动。
- 拖动后保存为手动顺序，刷新及重新登录仍保留。后续更新已有项目不打乱手动顺序；新项目排在已有手动序列前。页面不显示排序模式文字或恢复排序按钮。
- 发布者的个人分享页使用同一排序，过滤未发布项目后保留相对位置；分享页刷新后即可看到变更。管理员全局列表的排序是管理员自己的偏好，不改变其他发布者的分享页。

## 数据和接口

`projects.updated_at` 初次迁移按创建时间与最近成功发布时间中的较晚者回填；旧的改名时间没有历史数据，不推测。迁移重复执行不重置已有时间。

`project_list_preferences` 保存账号的 `updated/manual` 模式及递增 revision，`project_list_order` 保存该账号可见项目的序号；项目删除通过外键清除排序引用。列表与分享页查询使用同一优先级：手动模式下未纳入序列的新项目在前，其余按手动序号；自动模式依次按更新时间降序、创建时间降序、项目ID升序消除并列歧义。

`GET /api/v1/projects` 额外返回 `sortMode`、`sortRevision`，项目增加 `updatedAt`。列表与排序元信息在同一只读可重复读事务内获取。

`PUT /api/v1/projects/order` 接收：

```json
{"mode":"manual","projectIds":["完整可见项目ID序列"],"expectedRevision":0}
```

接口兼容 `mode: "updated"` 和空数组恢复自动模式，但页面不提供该操作入口。接口沿用有效账号、登录及 CSRF/Origin 校验；不接收目标账号，只能写当前账号偏好。手动提交检查重复、可见范围和完整列表，管理员仅可排序其自己的全局视图。按账号串行保存并检查 revision，多窗口覆盖返回409；项目列表增删引起的变化也拒绝旧提交。失败后界面恢复顺序并读取最新列表，不以本地缓存作为唯一存储。

排位动画在布局变更前测量位置，再使用 `translate/scale` 合成动画移动卡片，不逐帧修改高度、宽度或排列属性。命中检测使用未变形的最终网格槽位，避免移动中的卡片在静止指针下反复触发换位。快速反向拖动从当前可见位置接续；失败或冲突时重新排列，落位动画跟随最终位置。缩放窗口、失焦、离开页面会清除预览和浮层；减少动态效果偏好直接预览位置，不播放让位或落位动画。

## 本地验证

```powershell
node scripts/test-project-order-ui.mjs
node scripts/test-project-order-local.mjs
node scripts/test-project-welcome.mjs
```

第一项全部接口模拟，Chrome 验证鼠标空白拖动、刷新、按钮/文字保护、键盘移动、Escape取消、保存失败/多窗口冲突，以及真实触屏滚动和长按拖动、390/320px布局。额外验证松手前已有滑动动画且不写接口、指针静止不反复换位、连续变向取消不保存、松手落位、缩放窗口清理、减少动态效果和排序提示/恢复按钮均不存在。报告 `.local/project-order-ui-report.json`，拖动、落位及手机截图已查看。

第二项使用本地管理员登录和两个唯一临时项目，运行真实 ZIP 发布、原地址更新、回滚、坏包与改名，核对列表和匿名合集顺序。不会修改管理员排序偏好，也不创建账号；测试完成删除两个临时项目，并比较既有项目、更新时间及排序偏好快照。要求测试账号当前为自动模式，拒绝覆盖其手动偏好。报告 `.local/project-order-local-report.json` 为 `success:true, cleanup:true`。

后端 `TestProjectOrder...` 六项本地数据库测试使用随机隔离 schema，覆盖更新默认顺序、改名与无操作、手动排序及分享过滤、管理员与成员隔离、新项目/删除/恢复、非法及不完整序列、多窗口并发、幂等迁移、登录/停用/CSRF/Origin。全量后端测试（显式配置本地 `TEST_DATABASE_URL`）及 `go vet` 通过；无数据库配置时这些集成用例会跳过。前端构建、开场收起回归和已有真实 ZIP 界面验收通过。

以上为开发阶段的本地验收记录。随后经用户“好 更新上线”对本次改动的明确授权，已于2026-11-11上线，并在真实 HTTPS 服务验证最近更新、桌面/手机拖拽保存、刷新、分享过滤及同步、手动顺序不受再次更新影响，以及旧窗口/跨账号拒绝。专用临时账号、三个临时项目及排序偏好已清理，既有账号项目和排序状态保持不变。详情见[最近生产发布记录](PRODUCTION_GARAGE.md)。此次授权不延续到后续修改。
