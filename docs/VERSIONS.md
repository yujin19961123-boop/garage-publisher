# 项目版本与发布记录

在自己的项目卡片上点击“版本管理”，进入独立弹窗查看近期可切换版本与全部发布记录，并确认回滚。上传更新使用卡片上的“发布更新”入口，两者分开操作。固定分享地址不变，切换只改变它当前提供的内容，不复制文件、不创建新的上传记录。

## 版本与记录的区别

- 创建新版本成功后生成递增版本号。覆盖已有版本沿用原版本号，失败上传不占用版本号。
- 每个项目最多保留 5 个版本，包含当前版本。达到上限后，上传时必须选择一个已有版本覆盖。
- 切换旧版本不会腾出名额。覆盖后被替换的文件会异步清理，发布记录仍可查看。
- 不可用、已清理或文件缺失的版本不允许切换；界面显示其原因。

切换前确认目标版本。切换期间及有上传任务进行时不能重复操作。切换接口携带用户看到的当前版本 ID；如果其他操作已经改变当前版本，服务端返回冲突，刷新后重新确认，不会覆盖更新后的指向。对当前版本重复切换为无操作，不刷新成功发布时间。

项目所有者可上传和切换；管理员查看他人项目仍为只读，不增加代操作权限。公开链接不提供版本管理接口。现有项目删除会同时使版本入口失效，相关产物按平台清理策略回收。

## 备注与覆盖

创建或上传时可填版本备注。在版本管理中点铅笔图标，可单独保存备注，也可重传完整原型来覆盖该版本。未满 5 个版本时，“发布到”默认创建新版本，满额后只能选择覆盖。下拉框显示版本号、当前标记和文件更新时间。版本列表显示创建时间，发布记录显示更新时间，均精确到分钟。

覆盖成功后保留首次上传时间和版本号，更新文件时间。项目已发布时，覆盖当前版会立即更新分享链接的内容，覆盖历史版会在下次切换到该版本时生效。新文件校验失败时继续使用原文件。被覆盖的旧文件会清理，相关上传记录仍可查看。

点击当前版本的发布或取消发布图标即可直接操作。取消发布后，原链接暂时停止访问，个人合集也会隐藏该项目。版本和文件会保留，切换版本仍保持未发布，发布当前版本后恢复原链接。

在项目详情中创建新版本时，可以选择上传并发布，或仅保存版本。上传并发布会让原链接展示新版本。仅保存会保留链接的当前状态，新版本可在版本管理中使用。

## 文件状态

“可切换版本”仅列出保留范围内的候选，响应包含 `filesState=available|missing` 和 `canActivate`。全部发布记录区分 `available`、`cleanup_pending`、`cleaned`、`missing`；失败任务可能没有产物，此时状态为空。当前版本标记来自服务端，不依赖前端猜测。

旧发布记录可分页加载，每页最多20条。刷新记录不发起发布或切换。磁盘文件清理由异步流程完成，删除任务与用户切换必须由服务端协调，前端不能直接决定删除哪些目录。

“5份”是有效保留产物的上限；异步清理尚未完成时，磁盘上的过期目录可能短暂多于5份。清理任务未完成会阻止新上传，接口返回 `409 CLEANUP_PENDING`，避免不断累积磁盘占用；已有版本仍可查看和切换，单纯清理等待不同于正在发布。客户端应等待 `cleanupPending=false` 再上传。

清理使用持久任务并重新检查项目状态，安全排除当前版本与进行中发布，不按猜测的目录名删除。路径必须位于本项目数据范围内；失败任务保留并重试，不因删除失败丢失待处理记录。项目切换与清理协调使用服务端锁，不能通过前端禁用按钮代替。

## 旧数据迁移与完整性

已有发布数据通过幂等迁移补充成功版本号，重复启动不重复编号、不重排既有编号。对仍保留的旧产物补建完整性清单，使后续切换能校验实际文件；清单写入中断可恢复，不将半成品标记为已就绪。文件缺失或与清单不符时拒绝激活，不仅检查目录和首页是否存在。切换恢复该发布自身的路由模式，避免静态多页面与 SPA 模式互相混用。

旧数据迁移不创建新的用户上传记录，也不意味着缺失文件能从数据库恢复。实际文件不可用时保留可诊断状态，由所有者上传修复。列表中的文件状态是轻量检查，切换前会逐个文件校验完整性；目录存在不代表校验一定通过。

## 接口摘要

以下接口位于 `/api/v1`，均要求登录并校验项目所有者；管理员不获得他人项目的版本管理权限。

| 方法与路径 | 用途 |
|---|---|
| `GET /projects/{id}/versions` | 返回候选 `items`、`currentReleaseId`、`busy`、`cleanupPending`、`retentionLimit=5` |
| `GET /projects/{id}/deployments?cursor=...` | 发布记录游标分页，返回 `items` 与 `nextCursor` |
| `POST /projects/{id}/deployments` | 开始上传，支持选填 `note` 和用于覆盖的 `replaceReleaseId`。创建新版本时可用 `publishNow` 选择立即发布或仅保存 |
| `PATCH /projects/{id}/versions/{releaseId}` | 保存版本备注，请求体为 `{ "note": "…" }` |
| `PUT /projects/{id}/versions/{releaseId}/publication` | 设置当前版本的发布状态，请求体为 `{ "published": true }` 或 `{ "published": false }` |
| `POST /projects/{id}/versions/{releaseId}/activate` | 请求体携带 `expectedCurrentReleaseId`，原子切换并返回当前版本与成功时间 |

激活拒绝过期、缺失、不完整、他人所有或正在发布的目标；当前指向已变化时返回冲突，客户端刷新后重新确认。切换成功后固定访问地址保持不变。

## 本地验收

只在本地独立测试环境运行，先构建前端、启动已包含版本接口的后端。脚本只连接 `http://console.localhost:8080` 与本地原型地址，不支持生产 URL。需要本机 Chrome、前端依赖中的 Playwright 与 fflate，管理员凭据从本地 `.env` 读取，不打印到日志。

```powershell
node scripts/test-version-management.mjs
```

脚本创建一个带随机名称的临时项目，不新增成员，不修改现有项目；最终核对项目 ID、所有者与名称后删除，仅清理本次创建的项目，退出测试会话。失败报告会明确清理是否完成；如本地服务中途停止，恢复服务后应先处理报告中的临时项目，不要批量删除项目或目录。

验收覆盖：

1. 连续上传 5 个真实 ZIP，确认第 6 次新建被拒绝，已有版本和文件保留。
2. 切换旧版、切回新版，通过真实浏览器验证同地址 JavaScript、CSS、子页面与刷新。
3. 切换不产生上传记录，也不会腾出版本名额。
4. 入口缺失的 ZIP 失败时，不改变当前指向或已有版本集合。
5. 过期的当前版本条件返回冲突；切换当前版本不更新成功时间。
6. 正在上传时禁止切换；失败任务结束后可继续操作。
7. 成功与失败记录超过 20 条时可分页，无重复、无遗漏。
8. 桌面和手机视口显示到分钟的日期，版本操作图标对齐。键盘 Escape 取消、Enter 确认切换旧版并切回。
9. 满额时上传更新必须选择覆盖目标。覆盖当前版或历史版均保留版本号，失败时保留原文件。

结果保存在被 Git 忽略的 `.local/versions-result.json`，截图为 `.local/versions-desktop.png`、`.local/versions-mobile.png`。本脚本不创建其他所有者来测试越权；真实权限、管理员只读和并发事务边界由后端测试及独立 UI mock 检查补充，不应仅凭此脚本宣称覆盖全部权限。


后端另有13项 `TestVersions...` 测试，在本地数据库的独立随机 schema 中全部通过，覆盖幂等迁移、当前版与5版上限、并发清理保护、权限与过期条件、文件篡改、路径边界、分页、失败重试、路由模式恢复及清单写入中断恢复。运行方式及默认跳过行为见 [测试指南](VALIDATION.md)。
