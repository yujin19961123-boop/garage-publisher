# Next.js 静态原型

平台接收 Next.js 已导出的静态网页。使用 `output: 'export'` 构建后，上传生成的 `out` 文件夹（或改名后的导出文件夹）、其中全部内容或 ZIP，平台会自动识别，无需选择框架或路由模式。

需要保留完整导出内容，包括首页、各子页面、`_next` 资源和 Next 生成的页面数据文件。普通 `.next` 构建目录、需要 `next start` 的服务、Server Actions、SSR 和依赖服务端接口的应用不在当前托管范围。

官方说明：[Next.js 静态导出](https://nextjs.org/docs/app/guides/static-exports)。

## 平台适配

- 自动将已存在资源目录的地址放到项目路径下，例如 `/项目名/_next/`。
- 对明确的浏览器跳转、链接和资源属性，处理运行时计算出的本地地址；外部地址、未知路径和接口地址保持原样。
- 处理 Next Flight 数据中嵌套的 `_next` 资源地址，保留路由树和长度编码文本。
- 支持导出为 `页面.html` 和 `页面/index.html` 的访问方式。
- 对确认的 Next 导出，兼容页面数据请求与嵌套导出文件的路径差异。
- Next 导出使用静态页面查找，缺失页面不会错误返回 SPA 首页。

这不会把编译时的任意 Next 配置改造成服务器应用。未针对项目路径编译的原型，部分跳转可能由 Next 回退为整页加载；页面内的客户端交互仍需实际验证。不保证任意版本、运行时地址拼接或第三方资源均可自动修复。

## 本地回归

仓库保留了针对特定本地静态导出样例的浏览器验证脚本。需要先准备匹配的页面内容和 `/laobaby/` 项目路径；样例产物不随源码发布：

```powershell
node scripts/test-next-preview.mjs
```

脚本检查首页进入、桌面收件箱、子页刷新、浏览器前进后退、组件和移动端交互、中英文切换，以及本地资源错误、项目路径外请求和 JavaScript 错误。报告在被 Git 忽略的 `.local/next-preview-result.json`，截图在同目录。

应针对自己实际导出的产物运行检查，并记录完整结果。已发布的旧 Next 文件不会在原目录内被修改；所有者重新上传发布后应用新适配，项目地址保持不变。
